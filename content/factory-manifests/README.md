# Reviewed programme onboarding pilot

`tesu.json` is the explicit authoring roster for the eight existing canonical TESU ledgers. Three business-family entries bind their individual degree sources, shared-block authoring inputs, original pricing dates, context reviews and major requirements. The old `tesu-general-management` model remains a distinct reserved identity. This is a TESU family pilot; other schools' existing academic data remain authoritative and do not need a manifest to remain published.

The roster feeds business-major authoring, business metadata and exact course placement. A new reviewed entry joins its declared stages through data rather than another JavaScript ID list. A new academic family still needs an evidence-checking authoring adapter; this file does not establish unsupported school policies, receiving awards, programme applicability or course identities.

The current TESU adapter pins its reviewed catalog and November 26, 2026 evidence cohort. A later catalog or review cohort needs an explicitly versioned evidence basis; changing a manifest date does not refresh or reapprove the existing shared blocks.

To add a sibling in a supported family:

1. Retain and review its exact official degree and course sources using the existing source-capture workflow.
2. Add a distinct manifest entry with explicit school, catalog, modality, units, model, routes, input/output paths, source hashes, pricing and contextual bindings. Declare major courses, prerequisites and constraints, and the supported authoring stages. Shared output documents require an explicit matching `outputGroup`; accidental collisions fail.
3. Run the family's authoring adapter, exact receiving-award/placement review and contextual metadata authoring. Previously reviewed school blocks are reused only when the new degree's evidence proves their applicability.
4. Run `node scripts/pathway-factory/program-manifest.mjs --check` and the normal factory checks. The manifest checker makes no writes and verifies bindings against the retained canonical models and source bodies.
5. Publish only through the existing academic quality and complete-plan gates. Drafts and held entries never count as ready plans. Marketing retains its unresolved `MAR-3060` formal prerequisite and remains withheld.

The manifest deliberately records the stable receiving catalog label separately from each source's review date and the original price-source date. Registration never refreshes a source, approves a transfer, grants a student credit or migrates a saved plan.
